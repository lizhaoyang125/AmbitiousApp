> **最后更新**：2026-05-31
> **开发模式**：单人业余开发 (Indie Solo)
> **日均工时**：2 小时

---

## 〇、设计宣言 (Design Manifesto)

本项目的所有设计决策，遵循以下优先级：

1. **可完成性 > 完美性**：宁可做一个能跑的白块超市，也不要一个永远做不完的精美作品
2. **核心循环 > 外围系统**：物流仓储周循环是游戏的灵魂，所有外围系统围绕它服务
3. **数据驱动 > 硬编码**：所有商品、员工、店铺属性走 JSON 配置表，方便后期数值调整
4. **极简交互 > 花哨操作**：Click-to-Assign 是本项目的交互铁律，不引入拖拽系统
5. **UI 解决问题 > 场景解决问题**：能用面板搞定的，绝不增加场景复杂度

## 〇、名词定义 (Glossary)

| 术语 | 定义 |
|:-----|:-----|
| **体积单位 (Volume Unit)** | 仓库容量的最小计量单位。1 体积 = 一箱标准薯片的占用空间 |
| **周循环** | 游戏的核心时间单位，周一至周日为一个完整周期 |
| **营业期** | 白天 08:00-22:00，时间正常流逝，顾客出现 |
| **筹备期** | 夜晚，时间暂停，纯 UI 策略操作 |
| **爆仓** | 周一到货时，新货物体积 + 现有库存 > 仓库容量的状态 |
| **Click-to-Assign** | 点击物体 → 弹出菜单 → 选择操作的交互模式 |

## 一、 游戏概述 (Game Overview)

核心概念 (Logline)： 一款结合了"开罗式"店铺建造与"异星工厂式"硬核资源管理的2D上帝视角模拟经营游戏。玩家需要在一个严格的"周循环"内，精确计算进货量与库存，避免爆仓破产，逐步打造商业帝国。

游戏类型： 2D 商业策略 / 模拟经营 (Simulation / Management)

目标平台： Web Desktop 优先（Cocos Creator 构建），后续可拓展至移动端

美术风格： 像素风 / 简约 2D，角色采用基础像素小人，场景基于 TiledMap 瓦片地图

参考作品：

| 作品 | 借鉴要点 |
|:-----|:-----|
| 开罗系列（游戏发展国、百货商场物语） | 店铺建造的满足感、像素画风、数值驱动的成长曲线 |
| 异星工厂 (Factorio) | 硬核物流管理、体积/容量的精确计算、资源转换链 |
| 模拟便利店 (Convenience Stories) | 顾客AI行为、货架管理、收银排队 |

核心体验：

1. **极限仓储挑战**： 游戏的最大特色。进货不是瞬间完成，而是每周一早晨统一送达。玩家必须通过 UI 面板精确计算本周的进货量（体积）是否会超出仓库剩余容量（格子数）。

2. **解压感**： 看着空库房被填满，再看着顾客如流水线般将货物转化为金钱。

3. **节奏张弛有度**： 白天（营业期）观察客流、处理突发事件、感受赚钱的快感；夜晚（筹备期）时间暂停，纯 UI 驱动，静下心来复盘账单、规划下周进货和招募员工。

开发限制导向设计（日均 2 小时，单人）：

1. **极简交互**： 摒弃复杂的拖拽建造，采用"点击对象 -> 弹出菜单 -> 选择操作/指派人员"的 Click-to-Assign 模式。

2. **重度 UI，轻度物理**： 夜晚筹备期完全脱离场景，纯 UI 界面操作，大幅降低场景搭建和交互的开发成本。

3. **资源复用**： 严控美术需求，利用 TiledMap 构建基础场景，角色和商品使用基础像素/2D 资产。MVP 阶段允许用色块代替实物图片。

4. **配置驱动**： 所有数值走 JSON 配置表，策划调数值不需要改代码。

## 二、 核心循环与流程图 (Core Loop & Flow)

游戏围绕"周"和"日"进行严格的时间切分。

### 1. 宏观周循环 (Weekly Loop)

graph TD
    A[周一 08:00: 货物送达判定] --> B{是否爆仓?}
    B -- 是 --> C[扣除高额退货费/违约金]
    B -- 否 --> D[货物入库]
    C --> D
    D --> E[周一至周日: 每日昼夜循环]
    E --> F[周日 22:00: 结算本周周报]
    F --> G[玩家在夜晚UI规划下周进货]
    G --> A


### 2. 微观日循环 (Daily Loop)

graph TD
    A[08:00 营业开始] --> B[白天：动态营业期]
    B --> C(顾客生成受天气/日期影响)
    B --> D(商品消耗 & 资金增加)
    B --> E(突发事件: 脏污/排队/理货)
    B --> F[玩家: 点击指派员工处理事件]
    B --> G[22:00 营业结束]
    G --> H[夜晚：静态筹备期 (时间暂停)]
    H --> I[纯UI面板操作]
    I --> J(查看账本复盘)
    I --> K(人才市场招募/解雇)
    I --> L(进货市场加入购物车)
    I --> M[点击'下一天']
    M --> A


### 3. 昼夜状态切换表

| 阶段 | 时间 | 时间流逝 | 场景 | 玩家可操作 | AI 状态 |
|:-----|:-----|:-----|:-----|:-----|:-----|
| ☀️ 营业期 | 08:00 - 22:00 | 正常（可倍速） | MainScene 活跃 | Click-to-Assign 指派员工、处理突发事件 | 顾客生成并移动、员工执行任务 |
| 🌙 筹备期 | 22:00 - 次日 08:00 | 暂停 | NightUI 覆盖 | 查看账本、招募员工、加购进货、切换店铺 | 全部暂停 |

### 4. 每周特殊节点

| 时间点 | 事件 | 触发逻辑 |
|:-----|:-----|:-----|
| 周一 08:00 | 货物送达 + 爆仓判定 | 购物车商品结算入仓，超容则触发爆仓惩罚 |
| 周六、周日 | 周末客流 +50% | CustomerSpawner 调整生成频率 |
| 周日 22:00 | 周报结算 | 弹出本周盈亏汇总、热销/滞销商品排行 |

### 5. 玩家操作清单

☀️ **营业期可执行操作**：
- 点击货架 → 指派空闲员工优先补货
- 点击脏污 → 指派空闲员工前往打扫
- 点击收银台 → 指派/更换收银员
- 调整游戏速度（1x / 2x / 3x）
- 手动暂停游戏（ESC 或暂停按钮）

🌙 **筹备期可执行操作**：
- 大货市场：浏览商品、加减购物车、查看体积预警
- 账单复盘：查看当日/本周盈亏、商品销售排行
- 人才市场：浏览求职者、雇佣/解雇员工
- 产业总览（后期解锁）：查看名下店铺、盘下新店
- 点击「进入下一天」开始新一天

## 三、 详细系统设计 (System Design)

### 1. 时间与节奏系统 (Time Manager)

时间流逝： 白天正常流逝（可设置 1 倍/2 倍/3 倍速），夜晚时间静止。

日历： 区分工作日（周一至周五）和休息日（周六、周日）。休息日基础客流量提升 50%。

天气： 每天随机生成晴天或雨天。雨天总体客流降低 20%，但特定商品（如雨伞、方便面）需求权重增加。玩家可以在夜晚 UI 看到明天的天气预报。

### 2. 硬核物流与仓储系统（核心亮点）

库存容量： 仓库的容量以"体积单位"计算，初期仓库可能只有 100 体积单位。

进货规则：

- 玩家每天晚上可以在"大货市场"将商品加入购物车，但不立即送达。

- 统一送货： 所有购物车内的商品，统一在下周一早上 08:00 开门前一秒送达。

爆仓判定与惩罚：

- 周一 08:00，系统计算：新到货物总体积 + 当前仓库现有货物总体积。

- 如果总量 > 仓库最大容量，触发爆仓危机。

- 惩罚： 溢出的货物将被强制退回，玩家不仅得不到货物，还要按照退回货物总价的 X%（例如 30%）支付高额违约金。初期可能导致直接破产。

商品体积属性： 每个商品除了买入价、卖出价，都有一个极其重要的 Volume (体积) 属性。例如，一箱薯片体积为 1，一台冰箱体积为 10。

### 3. 极简交互系统 (Click-to-Assign)

在白天营业场景中，一切玩家操作基于点击：

- 点击货架： 弹出该货架的商品信息，如果有空闲理货员，可点击按钮强制优先补货。

- 点击脏污地面（事件）： 弹出指派 UI，显示当前空闲的员工头像，点击头像，该员工立刻寻路过去打扫。

- 点击收银台： 指派收银员。如果没有收银员，顾客结账会卡住并随时间降低满意度最终离开。

优势： 避免了复杂的拖拽射线检测、坐标对齐和物理碰撞，极大地降低了开发工作量，尤其适合单人开发者。

### 4. 员工与 HR 系统

招募： 在夜晚 UI 的人才市场招募，每日刷新 3 名求职者。

属性：

- MoveSpeed (移动速度)：影响理货和打扫走到目标点的时间。

- WorkEfficiency (工作效率)：影响收银速度、补货速度、打扫时间。

- DailySalary (日薪)：每天晚上结算时自动扣除。

状态： 员工有体力值，连续高强度工作体力下降，效率降低。夜晚自动恢复。如果发不出工资，员工第二天概率罢工或辞职。

### 5. 顾客 AI 系统 (Customer AI)

生成规则： 基于时间（早中晚波峰）、天气、日期（周末）动态计算每小时生成概率。

AI 行为树 (简化版)：

1. 进入超市大门。

2. 根据自己的购物清单（随机生成 1-3 件需求商品），寻路前往对应货架。

3. 到达货架，如果商品有库存 -> 拿取商品（货架表现减少，顾客头上冒出商品图标） -> 寻找下一个目标。

4. 如果商品无库存 -> 播放失落动画 -> 寻找下一个目标或直接去收银台。

5. 完成购物，寻路前往收银台排队。

6. 结账完成 -> 玩家增加金钱 -> 离开超市。

### 6. 经济与破产兜底系统 (Economy & Fallback)

收入： 销售商品赚取差价。

支出： 进货成本、员工日薪、爆仓违约金、可能的水电费。

新手保护期： 第 1 周（第 1-7 天）为免责期，爆仓不扣除违约金，只退货，防止新手玩家由于不熟悉体积机制上来就破产。

破产缓冲： 资金为负时不直接 Game Over。

- 变卖存货： 强制开启 UI，允许玩家以 5 折的低价抛售仓库中的存货换取现金。

- 如果变卖后仍为负数，且超过一定天数（如 3 天），则真正 Game Over。

### 7. 顾客满意度与流失系统 (Customer Satisfaction)

顾客不仅看是否买到东西，还看购物体验。满意度影响复购率和口碑传播。

满意度计算维度：

| 维度 | 权重 | 影响规则 |
|:-----|:-----|:-----|
| 🛒 商品可得性 | 50% | 清单中每缺一件商品 -20 分（100→80→60...） |
| ⏱️ 排队等待时间 | 30% | 超过 10 秒开始扣分，每多 5 秒 -10 分 |
| 🧹 环境整洁度 | 20% | 店内存在脏污时，所有顾客缓慢持续扣分 |

满意度等级与效果：

| 评分 | 等级 | 效果 |
|:-----|:-----|:-----|
| 90-100 | 😍 非常满意 | 该顾客下次光顾概率 +30%，有小概率带朋友来（+1 客流） |
| 60-89 | 😐 一般 | 正常光顾概率 |
| 30-59 | 😟 不满 | 下次光顾概率 -40% |
| 0-29 | 🤬 愤怒 | 直接离开且不再光顾，有概率留下差评（永久 -1 基础客流） |

顾客离店时结算满意度，当晚账单中展示今日顾客满意度均值和流失人数。

设计意图：玩家不能无限制地只追利润忽视体验。缺货太多、排队太长、地上太脏都会导致客源流失，形成"省成本 → 体验差 → 客流少 → 更省钱 → 破产"的死亡螺旋。

### 8. 店铺升级与扩建系统 (Store Upgrade & Expansion)

玩家不只能经营一家店，还能让每家店自己成长。

单店升级维度：

| 升级项 | 效果 | 升级条件 | 升级方式 |
|:-----|:-----|:-----|:-----|
| 📦 仓库扩容 | 仓库容量 +50 体积/级 | 花费金钱，逐级递增 | 夜晚筹备期 → 产业总览 → 选择店铺 → 升级 |
| 🏪 货架位扩充 | 可放置货架数 +2/级 | 花费金钱 + 店铺等级要求 | 同上 |
| 🎨 装修升级 | 提升顾客满意度 +5% 基准值 | 花费金钱 | 同上 |
| 👥 员工位扩充 | 最大员工数 +2/级 | 花费金钱 + 店铺客流量达标 | 同上 |

多店铺扩展：

| 里程碑 | 解锁内容 | 条件 |
|:-----|:-----|:-----|
| 🏪 第一家店（便利店） | 初始赠送 | 游戏开始即有 |
| 🏪 第二家店（服装店） | 解锁产业总览面板 | 第一家店连续盈利 2 周，花费金钱盘下 |
| 🏪 第三家店（电器店） | 解锁新品类 | 第二家店连续盈利 3 周，花费金钱盘下 |
| 🏪 第 N 家店 | 循环上述逻辑 | 产业总览中花钱盘下新店铺 |

店铺切换：
- 夜晚筹备期可自由切换名下任意店铺
- 切换店铺 → MainScene 重载对应店铺的地图 (TiledMap)、货架 Prefab、商品品类
- 各店铺独立核算盈亏，但资金池共用

设计意图：
- 初期（前 3-4 周）专注单店精细化运营
- 中期（第 4-8 周）开启多店扩张，考验跨店库存规划
- 单店升级是"深度"，多店扩张是"广度"，两条成长线并行

### 9. 事件系统框架 (Event System)

白天营业期会触发各类突发事件，需要玩家及时指派员工处理。统一的事件框架便于后续扩展新事件类型。

事件生命周期：

```
事件触发（定时/条件） → 场景生成标记物 → 玩家点击指派 → 员工处理 → 效果结算
```

事件类型：

| 事件 | 触发条件 | 场景表现 | 处理方式 | 未处理后果 |
|:-----|:-----|:-----|:-----|:-----|
| 🗑️ 地面脏污 | 每 2-3 小时随机刷新 1-2 处 | 地面出现脏污贴图 | 指派清洁工前往打扫（耗时 3 秒） | 环境整洁度持续下降，影响所有顾客满意度 |
| 📦 货架空缺 | 货架商品低于 20% 时自动触发 | 货架上出现空缺标记（红色闪烁） | 指派理货员从仓库补货 | 顾客逛到该货架时缺货扣分 |

设计意图：
- 事件是白天营业期"手忙脚乱"的主要来源，考验玩家的员工分配策略
- 事件系统框架支持后续通过 JSON 配置新增事件，无需改代码

## 四、 数据结构设计 (Data Models)

(基于项目 Assets 目录结构 `Scripts/Data/GameInterfaces.ts` 进行定义)

```typescript
// GameInterfaces.ts

// 商品定义
export interface IItemData {
    id: string;          // 商品唯一ID (e.g., 'item_cola')

    id: string;

    itemId: string;
    quantity: number;
}

// 每日账单记录
export interface IDailyLedger {

    income: number;
    expense: number;

// 顾客满意度
export interface ICustomerSatisfaction {

    penaltyPerSec: number;         // 未处理时每秒惩罚值
}

// 全局游戏状态 (存储在 DataManager 中)
export interface IGameState {
    money: number;
    currentDay: number;            // 总天数
    currentWeekDay: number;        // 1-7 (周一到周日)
    currentTime: number;           // 小时 (8 - 22)
    weather: 'Sunny' | 'Rainy';
    currentStoreId: string;        // 当前活跃店铺ID

    stores: Record<string, IStoreData>;        // 所有店铺数据
    shoppingCart: ICartItem[];                 // 本周准备进货的购物车
    employees: IEmployeeData[];                // 已雇佣员工

    // 当前店铺的快捷访问（指向 stores[currentStoreId] 的对应字段，运行时同步更新）
    warehouseCapacity: number;
    warehouseInventory: Record<string, number>;
    storeShelves: Record<string, number>;
}
```

## 五、 场景与界面规划 (Scenes & UI Flow)

StartScene (启动与主菜单)： 新游戏、继续游戏、设置。

MainScene (白天营业场景)：

- 渲染： 基于 TiledMap 构建地形。

- 实体： 货架、收银台、顾客、员工。

- HUD (Overlay)： 日期、时间、天气、当前资金、预估仓库占用条 (已用体积/总体积)。

NightUI Scene/Prefab (夜晚策略面板)：

- 全屏不透明 UI，遮挡背景。

- 大货市场 (Market Panel)： 商品列表、购买操作、购物车预警进度条（核心交互，当预估体积超过剩余空间时变红闪烁）。

- 账单复盘 (Ledger Panel)： 显示今日盈亏、滞销/热销商品。

- 人才市场 (HR Market)： 招聘新员工。
