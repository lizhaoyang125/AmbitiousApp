# 《无名之辈：白手起家》完整游戏策划书 V1.0

> **文档状态**：完整版 V1.0
> **最后更新**：2026-06-04
> **开发模式**：单人业余开发 (Indie Solo)
> **日均工时**：2 小时（严格限制，防爆肝防太监）
> **引擎**：Cocos Creator 3.x（Web Desktop 构建优先）

## 一、核心层（必须有）

### 1.1 设计宣言 / 设计目标

**一句话设计宣言：**

> "在有限的仓库空间里，用精确的计算和果断的决策，从一家小店起步，打造你的商业帝国。"

**设计优先级原则（按顺序）：**

1. **可完成性 > 完美性** — 宁可做一个能跑起来的白块超市，也不要一个永远做不完的精美作品
2. **核心循环 > 外围系统** — 物流仓储周循环是游戏的灵魂，所有外围系统围绕它服务
3. **数据驱动 > 硬编码** — 所有商品、员工、店铺属性走 JSON 配置表，方便后期数值调整
4. **极简交互 > 花哨操作** — Click-to-Assign 是本项目唯一交互模式，不引入拖拽系统
5. **UI 解决问题 > 场景解决问题** — 能用面板搞定的，绝不增加场景复杂度

---

### 1.2 游戏概述

**Logline（一句话描述）：**

一款结合"开罗式"店铺建造与"异星工厂式"硬核资源管理的2D上帝视角模拟经营游戏。玩家在严格的"周循环"内精确计算进货量与库存，避免爆仓破产，逐步打造商业帝国。

**游戏类型：** 2D 商业策略 / 模拟经营 (Simulation / Management)

**目标平台：** Web Desktop 优先（Cocos Creator 构建），后续可拓展至移动端

**美术风格：** 像素风 / 简约 2D，角色采用基础像素小人，场景基于 TiledMap 瓦片地图

**参考作品：**

| 作品 | 借鉴要点 |
|:-----|:-----|
| 开罗系列（游戏发展国、百货商场物语） | 店铺建造的满足感、像素画风、数值驱动的成长曲线 |
| 异星工厂 (Factorio) | 硬核物流管理、体积/容量的精确计算、资源转换链 |
| 模拟便利店 (Convenience Stories) | 顾客AI行为、货架管理、收银排队 |

**目标用户画像：**

| 维度 | 描述 |
|:-----|:-----|
| 核心用户 | 25-40 岁男性，喜欢模拟经营、策略类游戏（如开罗、异星工厂） |
| 潜在用户 | 喜欢解压类游戏（放置、掌柜类），有碎片化时间 |
| 消费意愿 | 愿意为单机品质付费，不排斥广告（但当前 MVP 为纯单机无内购） |
| 游玩场景 | 通勤、睡前、午休，每次 20-60 分钟 |
| 痛点 | 工作日时间碎片化，无法长时间连续游玩；厌烦复杂的操作和界面 |
| 需求 | 轻松上手但有深度，节奏可自行掌控，有明确的成长反馈 |

**核心体验三点：**

1. **极限仓储挑战**：游戏最大特色。进货不是瞬间完成，而是每周一早晨统一送达。玩家通过 UI 面板精确计算本周进货量（体积）是否会超出仓库剩余容量。

2. **解压感**：看着空库房被填满，再看着顾客如流水线般将货物转化为金钱，循环往复的满足感。

3. **节奏张弛有度**：白天（营业期）观察客流、处理突发事件、感受赚钱快感；夜晚（筹备期）时间暂停，纯 UI 驱动，静心复盘账单、规划下周。

**开发限制导向设计：**

| 限制 | 设计应对 |
|:-----|:-----|
| 日均 2 小时 | 极简交互（Click-to-Assign），重度 UI 轻物理，资源复用 |
| 单人开发 | 严控美术需求，白块替代图片；JSON 配置驱动，策划可独立调参 |
| 须完成 | 先跑通核心循环再迭代外围；任何技术难点卡超过 4 小时立刻启用 Plan B |

### 1.3 名词定义表

| 术语 | 定义 |
|:-----|:-----|
| **体积单位 (Volume Unit)** | 仓库容量的最小计量单位。1 体积 = 一箱标准薯片的占用空间 |
| **周循环 (Weekly Loop)** | 游戏的核心时间单位，周一至周日为一个完整周期 |
| **营业期 (Day Phase)** | 白天 08:00-22:00，时间正常流逝，顾客出现，AI 运行 |
| **筹备期 (Night Phase)** | 夜晚 22:00-次日 08:00，时间暂停，纯 UI 策略操作 |
| **爆仓 (Overstock)** | 周一到货时，新货物总体积 + 现有库存 > 仓库容量的状态 |
| **Click-to-Assign** | 点击物体 → 弹出菜单 → 选择操作的交互模式（本项目唯一交互方式） |
| **指派 (Assign)** | 玩家通过点击将空闲员工指派至特定任务（理货/收银/打扫）的行为 |
| **违约金 (Penalty)** | 爆仓时，玩家须按退货总价的 30% 支付违约金 |
| **连续盈利 (Consecutive Profit)** | 一家店连续 N 天日利润为正，用于判断是否可解锁新店铺 |
| **顾客满意度 (Satisfaction)** | 顾客购物后的综合评价，影响客流和复购率 |
| **新手保护期** | 游戏前 7 天（第 1 周），爆仓只退货不扣违约金 |

### 1.4 核心循环

游戏围绕"年 / 周 / 日"进行三层时间切分，形成嵌套循环。

> **时间系统**：从 1980 年 1 月 1 日开始计时，每 7 天 = 一周，每年约 52 周。年份用于标记时代背景（不影响 MVP 阶段核心功能，预留未来店铺类型按时代解锁）。

#### 1.4.1 宏观年循环 (Yearly Loop)

```
[每年 1 月 1 日]
        ↓
[年度经营报告（可选展示）]
        ↓
[进入新的一年]
        ↓
[年份 + 1]
```

#### 1.4.2 宏观周循环 (Weekly Loop)

```
[周一 08:00 货物送达]
        ↓
   [爆仓判定]
    ↙      ↘
爆仓 YES   爆仓 NO
    ↓         ↓
[扣退货费]  [货物入库]
    ↓         ↓
[货物入库]  [进入本周营业]
    ↓
[周一至周日 每日昼夜循环]
        ↓
[周日 22:00 周报结算]
        ↓
[玩家在夜晚UI规划下周进货]
        ↓
[进入下周一 08:00]
```

#### 1.4.2 微观日循环 (Daily Loop)

```
[08:00 营业开始]
        ↓
[白天：动态营业期]
 ├── 顾客生成（受天气/日期影响）
 ├── 商品消耗 & 资金增加
 ├── 突发事件（脏污/排队/理货）
 ├── 玩家：Click-to-Assign 指派员工
 └── 玩家：调速（1x/2x/3x）或暂停
        ↓
[22:00 营业结束]
        ↓
[夜晚：静态筹备期（时间暂停）]
 ├── 大货市场：加入购物车
 ├── 账单复盘：查看盈亏
 ├── 人才市场：雇佣/解雇
 ├── 产业总览：开新店/升级（后期）
 └── 点击「进入下一天」
        ↓
[进入下一天 08:00]
```

#### 1.4.3 昼夜状态切换

| 阶段 | 时间 | 时间流逝 | 场景 | 玩家操作 | AI 状态 |
|:-----|:-----|:-----|:-----|:-----|:-----|
| ☀️ 营业期 | 08:00-22:00 | 正常（可 1/2/3x） | MainScene 活跃 | Click-to-Assign 指派、处理事件、调速暂停 | 顾客生成并移动、员工执行任务 |
| 🌙 筹备期 | 22:00-次日 08:00 | 暂停 | NightUI 覆盖 | 查看账本、招募、进货、切换店铺 | 全部暂停 |

#### 1.4.4 每周特殊节点

| 时间点 | 事件 | 触发逻辑 |
|:-----|:-----|:-----|
| 周一 08:00 | 货物送达 + 爆仓判定 | 购物车商品结算入仓，超容则触发爆仓惩罚 |
| 周六、周日 | 周末客流 +50% | CustomerSpawner 调整生成频率 |
| 周日 22:00 | 周报结算 | 弹出本周盈亏汇总、热销/滞销商品排行 |

### 1.5 系统设计

#### 1.5.1 时间与节奏系统 (TimeManager)

- **时间流逝规则**：白天正常流逝（可设置 1x/2x/3x 倍速），夜晚时间静止
- **换算比例**：现实 1 秒 = 游戏内 1 分钟
- **日历系统**：区分工作日（周一至周五）和休息日（周六、周日）。休息日基础客流量 +50%
- **天气系统**：每天随机生成晴天或雨天。雨天总体客流 -20%，雨天特定商品（雨伞、方便面）需求权重增加
- **事件派发**：08:00 派发 `EVENT_DAY_START`，22:00 派发 `EVENT_DAY_END`，使用观察者模式（EventDispatcher）

#### 1.5.2 硬核物流与仓储系统（核心亮点）

- **仓库容量**：以"体积单位"计算，初期仓库约 100 体积单位
- **进货规则**：
  - 玩家每天晚上可在"大货市场"将商品加入购物车，但不在当晚送达
  - 所有购物车内商品统一在下周一 08:00 送达
- **爆仓判定**：周一 08:00，系统计算 `新到货物总体积 + 现有库存总体积 > 仓库最大容量` 即触发爆仓
- **爆仓惩罚**：溢出货物强制退回，玩家按退货总价 30% 支付违约金（新手保护期免责）
- **商品体积属性**：每个商品有 Volume 属性（如一箱薯片体积 1，一台冰箱体积 10）

#### 1.5.3 Click-to-Assign 交互系统

- **点击货架** → 弹出该货架商品信息；空闲理货员存在时，可点击按钮强制优先补货
- **点击脏污地面（事件）** → 弹出指派 UI，显示空闲员工头像，点击后员工立刻寻路过去打扫（耗时 3 秒）
- **点击收银台** → 指派/更换收银员；无收银员时顾客结账卡住并随时间降低满意度
- **点击空白处** → 取消当前选中，气泡菜单关闭

优势：避免复杂的拖拽射线检测、坐标对齐和物理碰撞，极大降低开发工作量。

#### 1.5.4 员工与 HR 系统

- **招募**：夜晚 UI 人才市场招募，每日刷新 3 名求职者
- **员工属性**：
  - `moveSpeed`：影响寻路时间
  - `workSpeed`：影响收银速度、补货速度、打扫时间
  - `dailySalary`：每天晚上结算时自动扣除
- **员工状态**：Idle（空闲）/ Assigned（已指派）/ Working（工作中）/ Resting（休息中）
- **体力机制**：连续高强度工作体力下降，效率降低；夜晚自动恢复；发不出工资则概率罢工或辞职

#### 1.5.5 顾客 AI 系统

- **生成规则**：基于时间（早中晚波峰）、天气、日期（周末）动态计算每小时生成概率
- **AI 行为树**：
  1. 进入超市大门
  2. 根据购物清单（随机 1-3 件需求商品）寻路前往对应货架
  3. 有库存 → 拿取商品（头上冒商品图标）→ 找下一个目标；无库存 → 失落动画 → 直接去收银台
  4. 完成购物，寻路前往收银台排队
  5. 结账完成，玩家增加金钱，顾客离开
- **对象池**：预加载 20 个顾客实例，回收复用，防止卡顿

#### 1.5.6 经济与破产兜底系统

- **收入**：销售商品赚取差价
- **支出**：进货成本、员工日薪、爆仓违约金
- **新手保护期**：第 1 周（Day 1-7）为免责期，爆仓只退货不扣违约金
- **破产触发条件**：结算日（周日 22:00）时，若剩余资金不足以支付员工工资和本周应付款项，进入破产清算
- **破产清算流程**：
  1. 系统弹出「破产清算面板」，禁止其他操作
  2. 面板展示当前负余额和仓库中所有商品列表（名称 / 进货价 / 半价 = 进货价 × 50%）
  3. 玩家自行勾选要清仓的商品及数量，系统实时计算回血金额（按进货价 50% 折算）
  4. 玩家确认后，资金恢复为正值（或降至 0），清仓商品从仓库永久扣除
  5. 若玩家没有勾选任何商品或仓库为空，则直接 Game Over
- **Game Over**：游戏结束，弹出最终周报，可选择重新开始

#### 1.5.7 顾客满意度与流失系统

| 维度 | 权重 | 规则 |
|:-----|:-----|:-----|
| 商品可得性 | 50% | 清单每缺一件 -20 分 |
| 排队等待时间 | 30% | 超过 10 秒开始扣分，每多 5 秒 -10 分 |
| 环境整洁度 | 20% | 店内存在脏污时所有顾客持续扣分 |

| 评分 | 等级 | 效果 |
|:-----|:-----|:-----|
| 90-100 | 😍 非常满意 | 下次光顾概率 +30%，小概率带朋友来 |
| 60-89 | 😐 一般 | 正常光顾概率 |
| 30-59 | 😟 不满 | 下次光顾概率 -40% |
| 0-29 | 🤬 愤怒 | 直接离开不再光顾，有概率永久 -1 基础客流 |

#### 1.5.8 店铺升级与多店铺系统

**单店升级维度**：

| 升级项 | 效果 | 升级方式 |
|:-----|:-----|:-----|
| 仓库扩容 | 容量 +50 体积/级 | 夜晚筹备期 → 产业总览 → 选择店铺 → 升级 |
| 货架位扩充 | 可放置货架数 +2/级 | 同上 |
| 装修升级 | 顾客满意度 +5% | 同上 |
| 员工位扩充 | 最大员工数 +2/级 | 同上 |

**多店铺解锁**：

| 里程碑 | 解锁条件 |
|:-----|:-----|
| 第一家店（便利店） | 游戏开始即有 |
| 第二家店（服装店） | 当前余额 ≥ 30,000 元，花费金钱盘下 |
| 第三家店（电器店） | 当前余额 ≥ 30,000 元，花费金钱盘下 |

> 💡 **拓展功能预留**：店铺类型按时代解锁（1990 年服装店、2000 年电子店等），放入 v1.1 规划。

**店铺切换**：夜晚筹备期可自由切换同名店铺 → MainScene 重载对应 TiledMap 和货架 Prefab；各店铺独立核算盈亏，资金池共用。

#### 1.5.9 事件系统框架

白天营业期触发各类突发事件，通过 JSON 配置扩展。

**事件生命周期**：`触发（定时/条件）→ 场景生成标记物 → 玩家点击指派 → 员工处理 → 效果结算`

| 事件 | 触发条件 | 场景表现 | 处理方式 | 未处理后果 |
|:-----|:-----|:-----|:-----|:-----|
| 🗑️ 地面脏污 | 每 2-3 小时随机刷新 1-2 处 | 地面出现脏污贴图 | 指派清洁工（耗时 3 秒） | 所有顾客满意度持续下降 |
| 📦 货架空缺 | 货架商品低于 20% 时触发 | 货架红色闪烁 | 指派理货员从仓库补货 | 顾客到此货架缺货扣分 |

## 二、体验层（中大型项目标配）

### 2.1 玩家旅程 / 心流曲线

#### 第 1 分钟 — 新手引导期

**目标**：让玩家快速理解"进货→卖货"的核心循环，不被任何 UI 困惑。

| 时间点 | 玩家在干什么 | 情绪状态 | 设计要点 |
|:-----|:-----|:-----|:-----|
| 0:00-0:10 | 观看 Logo 和标题自动闪过 | 好奇 | 自动过渡，不需点击 |
| 0:10-0:20 | 看到"新游戏"按钮，点击进入 | 期待 | 按钮足够大，反馈明确 |
| 0:20-0:40 | 场景加载，出现"第 1 天 周一 08:00"，HUD 浮现 | 初步理解 | HUD 清晰标注当前资金和时间 |
| 0:40-1:00 | 自动弹出新手引导气泡："欢迎来到你的小店！今天是第一天，先熟悉一下环境吧" | 被引导 | 强制引导 1 个步骤，点"我知道了"继续 |

#### 第 5 分钟 — 自由探索期

**目标**：让玩家亲手操作一次完整的 Click-to-Assign，理解"发现问题 → 点它 → 派员工 → 解决"的闭环。

| 时间点 | 玩家在干什么 | 情绪状态 | 设计要点 |
|:-----|:-----|:-----|
| 1:00-2:00 | 自由点击场景中的货架/收银台/员工 | 探索 | 每个可交互对象有微妙的高亮提示 |
| 2:00-3:00 | 顾客出现并开始在货架间移动 | 惊喜 | 第一个顾客从大门走进时播放音效 |
| 3:00-4:00 | 脏污事件触发（地面出现脏污标记）| 轻微紧张 | 同时弹出引导："出现脏污了！点击它指派员工打扫" |
| 4:00-5:00 | 玩家点击脏污 → 气泡菜单出现 → 点击员工头像 → 员工走过去打扫 → 问题解决 | 满足/成就感 | 员工完成任务时播放清脆音效，脏污消失 |

#### 第 30 分钟 — 策略决策期

**目标**：玩家第一次经历 22:00 夜晚切换，进入纯策略 UI，感受到与白天完全不同的节奏。

| 时间点 | 玩家在干什么 | 情绪状态 | 设计要点 |
|:-----|:-----|
| 25:00 | 22:00 到达，时间暂停，NightUI 全屏覆盖弹出 | 轻微惊讶 | NightUI 遮罩从上方滑入，有轻快的音效 |

```
情绪
  ▲
  │    ████
  │   █    ██                              ████
  │  █      █                            █    █
  │ █        █    ████                  █      █
  │█          █▄▄█    █                █        █
```

- **0-5 分钟**：引导为主，控制信息量，每个步骤只给 1 个操作提示
- **5-20 分钟**：自由探索 + 简单反馈，鼓励玩家多用 Click-to-Assign
- **20-30 分钟**：节奏变慢，夜晚 UI 给玩家思考和决策空间
- **30 分钟+**：进入稳态循环，每局约 7 天，玩家熟悉后节奏加快

### 2.3 数值模型

#### 核心经济循环数学公式

**每日净利润**：
```
日净利润 = 日收入 - 日支出
日收入 = Σ(商品售价 × 销售数量)
日支出 = Σ(员工日薪) + 进货成本（周一结算）
```

**爆仓判定公式**：
```
总进货体积 = Σ(商品体积 × 进货数量)
周一仓库占用 = 当前库存总体积 + 总进货体积
爆仓条件 = 周一仓库占用 > 仓库容量
```

**满意度计算公式**：
```
满意度总分 = (商品可得性得分 × 0.5) + (排队等待得分 × 0.3) + (环境整洁度 × 0.2) + 装修 bonus
商品可得性得分 = 100 - (缺货商品数 × 20)
排队等待得分 = max(0, 100 - (等待秒数 - 10) / 5 × 10)
```

**客流动态计算**：
```
基础客流 = 10 人/小时
天气修正 = 晴天 × 1.0 / 雨天 × 0.8
周末修正 = 工作日 × 1.0 / 周末 × 1.5
满意度修正 = 满意度 >= 90 ? × 1.3 : 满意度 >= 60 ? × 1.0 : × 0.6
实际客流 = floor(基础客流 × 天气修正 × 周末修正 × 满意度修正)
```

### 2.4 关卡/阶段设计

游戏以"天数"为阶段单位，每个阶段有明确的解锁条件和体验差异。

#### 阶段一：Day 1-7（新手保护期）

- **解锁条件**：游戏开始即解锁
- **体验特点**：
  - 仓库容量 100 体积
  - 商品种类 5 种（生鲜为主）
  - 爆仓只退货不扣违约金
  - 强制新手引导全程开启
- **玩家目标**：熟悉 Click-to-Assign 和夜晚进货流程

#### 阶段二：Day 8-21（正式运营期）

- **解锁条件**：Day 8 自动解锁
- **体验特点**：
  - 爆仓开始收取 30% 违约金
  - 新商品种类开放（服装类）
  - 天气系统正式激活
  - 新手引导关闭，玩家自由运营
- **玩家目标**：学会精确计算进货量，避免爆仓破产

#### 阶段三：Day 22-42（多店扩张期）

- **解锁条件**：当前余额 ≥ 30,000 元
- **体验特点**：
  - 可花费金钱盘下第二家店（服装店）
  - 各店铺独立地图（TiledMap）和商品品类
  - 跨店库存管理成为新的策略维度
- **玩家目标**：管理多店铺，优化资源分配

#### 阶段四：Day 43+（成熟经营期）

- **解锁条件**：当前余额 ≥ 30,000 元
- **体验特点**：
  - 可解锁第三家店（电器店），商品体积更大
  - 仓库扩容和装修升级系统全开
  - 员工体力系统全开（效率分级）
- **玩家目标**：打造稳定盈利的商业帝国

| 🗑️ 地面脏污 | 每 2-3 小时随机 1-2 处 | 指派清洁工（3 秒）| 满意度持续下降 |
| 📦 货架空缺 | 货架库存 < 20% | 指派理货员补货 | 顾客缺货扣分 |
| 👥 收银台拥堵 | 排队人数 > 3 | 指派更多收银员或调整 | 等待超时，满意度下降 |
| 💰 资金告急 | Money < 进货成本 | 弹出警告，建议抛售 | - |

### 3.6 游戏场景与细节

#### 场景架构

| 场景 | 说明 | 动态要素 |
|:-----|:-----|:-----|
| StartScene | 启动与主菜单 | 静态 Logo + 按钮 |
| MainScene | 营业核心场景（动态）| 根据店铺类型动态挂载 TiledMap、货架、顾客、员工 |
| NightUI（Prefab 叠加）| 夜晚策略面板 | 全屏 UI，不切换场景 |

#### 地图规划

| 店铺 | TiledMap 文件 | 尺寸 | 货架密度 |
|:-----|:-----|:-----|:-----|
| 便利店 | store_basic.tmx | 20×15 格 | 中等（6 货架）|
| 服装店 | store_clothing.tmx | 24×18 格 | 高（8 货架，衣架）|
| 电器店 | store_electronics.tmx | 28×20 格 | 低（5 货架，大体积）|

#### 细节交互

- 顾客头部会根据当前状态显示气泡：💭（思考下一步）→ 🛒（拿着商品）→ 😠（缺货不满）→ 💰（结账完成）
- 货架缺货时红色闪烁，商品被拿走后库存数字 -1
- 员工被指派时头顶出现箭头指向目标点
- 资金变化时右上角数字有 +N 飘字动画（绿色上升，红色下降）

### 4.3 风险与 Plan B

| 难点 | 风险等级 | Plan B |
|:-----|:-----|:-----|
| A* 寻路死锁/角色卡墙角 | 🔴 高 | 移动超过 5 秒未到达目标 → 强制瞬移到目标坐标 |
| 排队系统过于复杂 | 🔴 高 | 降级为"收银台前最多 3 人排队"，超出顾客直接瞬移结算 |
| Cocos 粒子系统难上手 | 🟡 中 | 改用 Sprite 帧动画 + Tween 位移动画模拟金币特效 |
| 多店铺动态重载地图 Bug | 🟡 中 | 切换店铺时清空场景节点，重新加载新地图 Prefab（允许短暂黑屏）|
| A* 库引入失败 | 🟡 中 | 手写 BFS 寻路替代，损失部分性能但保证能跑 |
| 数值崩坏（第 1 周破产）| 🟢 低 | 暴力兜底：自动延长新手保护期到第 2 周，弹出重开建议 |
