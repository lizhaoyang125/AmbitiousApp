# 《无名之辈：白手起家》终极开发排期表

---

## 📊 项目开发概览

| 项目 | 说明 |
|:-----|:-----|
| **开发模式** | 单人业余开发 (Indie Solo) |
| **时间预算** | 每天严格限制 **2 小时**（防爆肝、防太监） |
| **总计周期** | 8 个冲刺周 (Sprint)，共计 56 天 / 112 工作小时 |
| **MVP 核心目标** | 跑通 `白天接待顾客赚钱 → 晚上计算体积进货 → 周一早晨防爆仓` 的核心循环 |

> 💡 游戏支持多品类店铺，MVP 阶段先实现第一家基础店铺，随后通过复用架构扩展服装店、电器店等。

---

## 🗺️ 核心场景规划 (Scene Architecture)

为了保证性能和逻辑的解耦，游戏将划分为 **3 个主场景（Scene）**。通过动态加载技术，我们将用最少的场景支持无限多的店铺品类。

### 1️⃣ 启动场景 `StartScene.scene`

| 属性 | 说明 |
|:-----|:-----|
| **作用** | 游戏的入口，负责轻量级的加载和初始化 |

**功能：**

- 展示工作室 Logo、游戏标题《白手起家》
- 提供 `New Game` / `Continue` 按钮

> 🔧 点击 `Continue` 时，调用 `DataManager` 读取本地存档，数据准备完毕后再跳转到下一个场景。

---

### 2️⃣ 通用营业场景 `MainScene.scene`

| 属性 | 说明 |
|:-----|:-----|
| **作用** | 游戏的核心物理游玩区域（动态），所有角色的移动、物理交互都在这里发生。这是一个通用容器，支持所有品类的店铺 |

**功能：**

- **动态环境渲染** — 不写死某一个地图，而是根据玩家当前进入的店铺类型（如便利店、服装店），动态挂载对应的 TiledMap 节点
- **实体承载** — 动态生成和销毁货架 (Shelves/Racks)、顾客 (Customers)、员工 (Employees)
  - 服装店 → 生成 `衣架 Prefab`
  - 便利店 → 生成 `普通货架 Prefab`
- **寻路网格** — 根据当前动态加载的地图，生成 A\* 寻路网格数据
- **日间 UI (HUD)** — 顶部悬浮栏（显示时间、金钱、天气、当前店铺名、仓库使用率）

> 🔧 晚上 22:00 时，**不切换场景**，而是暂停此场景内的物理和 AI 时钟，并激活"夜晚策略 UI"。

---

### 3️⃣ 夜晚纯 UI 场景（通过 `NightUI.prefab` 叠加）

> ⚠️ 独立开发者强烈建议：直接在 MainScene 顶层弹出一个全屏、不透明的 `NightUI.prefab` 遮盖住底层，**而不是真正切换 Scene**。

| 属性 | 说明 |
|:-----|:-----|
| **作用** | 时间静止时的硬核策略阶段，也是玩家进行"多店铺管理"的宏观层 |

**功能：**

- 🛒 **进货市场 (Market)** — 核心的体积计算、加购物车功能（按商品品类划分，如生鲜、服饰、电子）
- 🏢 **产业总览 (Empire Map)** — 在这里查看你拥有的所有店铺，或者花钱"盘下新店"
- 📊 **财务账单 (Ledger)** & 👥 **人力资源 (HR)** — 管理整个商业帝国的报表和员工

## 📁 Assets 目录结构规范

一个极其清晰的 assets 目录，能让你在开发到第 50 天时依然保持清醒。基于多品类店铺的需求，资源按类型严格分类：

```
assets/
│
├── Scenes/                  # 🟢 存放所有场景文件
│   ├── StartScene.scene     # 启动菜单
│   └── MainScene.scene      # 通用营业场景 (承载所有类型的店铺)
│
├── Scripts/                 # 🔵 所有 TypeScript 代码 (按职责严格分类)
│   ├── Data/                # 纯数据接口与模型
│   │   └── GameInterfaces.ts# 定义 IItem, IEmployee, IGameState, IStore 等
│   ├── Managers/            # 全局单例管理器
│   │   ├── DataManager.ts   # 掌管钱、跨店库存、多店铺数据
│   │   ├── TimeManager.ts   # 掌管白天黑夜、每周流转、天气
│   │   ├── ConfigManager.ts # 读取并解析 JSON 配置表到内存字典
│   │   └── PoolManager.ts   # 对象池 (极其重要！用于复用顾客，防止卡顿)
│   ├── Controllers/         # 挂载在实体节点上的逻辑控制脚本
│   │   ├── CustomerController.ts # 顾客AI与寻路
│   │   ├── EmployeeController.ts # 员工打扫/理货AI
│   │   └── ShelveController.ts   # 通用货架逻辑
│   ├── UI/                  # 挂载在 UI 面板上的视图脚本
│   │   ├── HUDController.ts # 白天顶部的钱、时间显示
│   │   ├── NightMarketUI.ts # 晚上的大货市场面板逻辑
│   │   └── EmpireMapUI.ts   # 产业总览/开新店面板逻辑
│   └── Utils/               # 通用工具类
│       └── AStarPathfinding.ts # A* 寻路算法文件
│
├── Prefabs/                 # 🟡 预制体 (随时可以复用的节点)
│   ├── Entities/
│   │   ├── Customer.prefab
│   │   └── Employee.prefab
│   ├── Props/               # 支持多店铺的静态交互物件
│   │   ├── Shelve_Food.prefab    # 食品货架
│   │   ├── Shelve_Cloth.prefab   # 服装展架
│   │   ├── Cashier.prefab   # 收银台
│   │   └── Trash.prefab     # 脏污垃圾 (突发事件)
│   └── UI/
│       ├── NightUI.prefab   # 夜晚全屏面板
│       └── AlertBox.prefab  # 通用警告弹窗
│
├── Textures/                # 🟣 美术图片资源 (Sprites)
│   ├── Characters/          # 角色图集 (C1~C5等)
│   ├── Props/               # 不同店铺货架、收银台图片
│   ├── Goods/               # 按品类细分的商品图标
│   │   ├── Food/
│   │   ├── Clothing/
│   │   └── Electronics/
│   └── UI/                  # 按钮、面板背景、图标
│
├── Tileds/                  # 🟤 瓦片地图资源 (多店铺地图)
│   ├── store_basic.tmx      # 初始便利店地图
│   ├── store_clothing.tmx   # 中级服装店地图
│   └── *.tsx / *.png        # 地图依赖的图集
│
├── Audio/                   # 🎵 声音资源
│   ├── BGM/
│   └── SFX/
│
└── resources/               # ⚪ 动态加载的资源
    └── Data/                # JSON 静态配置表
        ├── Items.json       # 商品属性表 (包含 storeType 字段区分去哪卖)
        ├── Stores.json      # 店铺配置表 (开新店的成本、可用货架数量等)
        └── Employees.json   # 员工属性表
```

### Sprint 1: 核心数据流与时间引擎（第 1 周）

- [ ] **Day 2: 静态配置表读取**

  - 编写 `ConfigManager.ts` 读取并解析 JSON 到内存字典中

- [ ] **Day 3: 数据大管家 (DataManager - 基础)**
  - 编写 `DataManager.ts` 单例
  - 实现核心状态维护（资金、当前天数）、`addMoney()`, `costMoney()`

- [ ] **Day 4: 数据大管家 (DataManager - 仓储)**
  - 实现购物车数据结构 `ICartItem[]`
  - 实现添加购物车、实时计算当前购物车商品总体积的函数
  - 实现按"店铺"维度的库存管理，支持跨店库存数据
  - 接入 `sys.localStorage` 实现简单的存读档

- [ ] **Day 5: 游戏时间引擎 (TimeManager - 基础)**

### Sprint 2: 夜晚硬核进销存系统（第 2 周）

> 🎯 **目标**：完成游戏最核心的策略难点——防爆仓与结算。

- [ ] **Day 8: 夜晚全屏 UI 骨架**
  - 拼装 `NightUI.prefab`，设置黑色半透明遮罩
  - 划分顶栏（天数、资金）和 **4 个标签页**：进货、账单、人事、产业总览（产业总览初期锁定，Sprint 6 解锁）

- [ ] **Day 9: 大货市场界面 (Market UI)**
  - 读取 `Items.json`，用 `ScrollView` 动态生成商品卡片
  - 卡片上加粗标红显示该商品的 **[体积: X]**
  - 支持按商品品类划分 Tab 切换（如生鲜、服饰、电子）

- [ ] **Day 10: 购物车防爆仓预警（核心交互）**
  - 制作底部购物车面板：当前占用体积 / 仓库总容量
  - 每次点击 `+1`，立即计算。如果预估超载，进度条变红并播放警告动画
  - 实时计算跨店铺的总体积，一旦超载，进度条变红闪烁

- [ ] **Day 11: 时间系统与 UI 接轨**
  - 监听 `EVENT_DAY_END`：时间静止，弹出 `NightUI`
  - 制作 `[进入下一天]` 按钮：点击后关闭 UI，时间恢复

- [ ] **Day 12: 极简人事与账单**
  - 拼装 HR 面板，静态读取 3 个假员工数据，点击"雇佣"写入 `DataManager`
  - 拼装 Ledger 面板，展示今日收入支出文本

- [ ] **Day 13: 审判日！周一早晨进货结算**
  - 监听时间引擎，判断今天是星期一 08:00
  - 结算代码：检查 `购物车体积 + 现有库存体积 > 总容量` 是否成立
  - ✅ 未爆仓 → 购物车清空，转移至真实库存，扣除资金

- [ ] **Day 14: 爆仓破产惩罚**
  - 💥 爆仓 → 计算超出的商品价值，乘以惩罚系数（如 30% 违约金）直接扣钱
  - 弹出通用警告框 `AlertBox.prefab`：**"物流拒收！你支付了高额违约金！"**

**✅ Sprint 2 验收标准：**
- [ ] 夜晚 22:00 自动弹出 NightUI，时间暂停
- [ ] 大货市场可浏览商品，购物车体积进度条实时更新
- [ ] 超容时进度条变红闪烁
- [ ] 手动快进 7 天，周一 08:00 触发货物送达和爆仓判定
- [ ] 未爆仓：购物车清空 → 库存增加 → 扣钱；爆仓：弹出 AlertBox → 扣违约金
- [ ] 点击「进入下一天」关闭 NightUI，时间恢复

### Sprint 4: 寻路网格与基础 AI（第 4 - 5 周）

> 🎯 **目标**：让满屏的代码变成看得见的"人头攒动"。

- [ ] **Day 22-23: A\* 寻路植入**
  - 引入轻量级 A\* TypeScript 库
  - 解析 TMX 地图的 Obstacle（障碍）层，生成二维寻路网格 `0(可走) / 1(不可走)`

- [ ] **Day 24: 角色移动控制器**
  - 编写 `CharacterMovement.ts`，接收一条坐标路径数组
  - 使用 Cocos `tween` 逐个节点平移，根据朝向翻转角色的 Sprite (`scaleX = -1`)

- [ ] **Day 25-26: 员工状态机 (FSM)**
  - 编写 `EmployeeAI.ts`
  - 流程：接到"理货"任务 → A\* 寻路到仓库坐标点 → 计时器等待 2 秒 → A\* 寻路到货架坐标点 → 待命

- [ ] **Day 27: 顾客生成器 (Spawner)**
  - 编写 `CustomerSpawner.ts`，对象池 (`PoolManager`) 预加载 20 个顾客实例
  - 白天每隔 X 秒在超市大门坐标 Spawn 一个顾客

- [ ] **Day 28: 顾客购物 AI（逛货架）**
  - 顾客生成时，随机分配 1 个需求商品
  - 获取该商品所在货架的坐标 → A\* 寻路过去 → 计时器等待挑选

- [ ] **Day 29: 顾客结账 AI（走向收银台）**
  - 挑选结束后 → 寻路到收银台等待点

- [ ] **Day 30-32: 收银台排队系统（最难点之一）**
  - 编写 `QueueManager.ts`，顾客到达收银台时，检查是否有人
  - 有人则排在其身后（坐标 `y - 50`），前一个人结账走后，队列里的人自动往前补位（Tween 平移）

- [ ] **Day 33-35: 寻路穿模与 AI 死锁修复**
  - 顾客卡在墙角？员工走不动？用这三天耐心解决所有寻路边界问题
  - 不强求碰撞躲避，允许部分穿模，保证流程不中断

**✅ Sprint 4 验收标准：**
- [ ] 员工被指派后，能 A* 寻路到目标点并执行任务（等待计时器跑完）
- [ ] 顾客定时从大门生成，走到随机货架停留，再到收银台排队
- [ ] 排队时顾客自动纵向排列，前面的人结账后后面的人自动补位
- [ ] 顾客人数高于 10 人时无明显卡顿（对象池回收正常）
- [ ] 员工和顾客不会卡死在障碍物前（允许强行瞬移兜底）

### Sprint 5: 核心业务闭环（第 6 周）

> 🎯 **目标**：东西卖出去，钱收回来，工资发出去。

- [ ] **Day 36: 货架真实库存扣减**
  - 顾客停留在货架时，真正读取 `DataManager` 的该货架存量
  - 库存 > 0 → 拿走，头上冒气泡 | 库存 = 0 → 冒生气气泡，直接去出口

- [ ] **Day 37: 结账交钱逻辑 + 顾客满意度结算**
  - 顾客在收银台遇到"正在工作"的员工，根据员工 `WorkEfficiency` 倒计时
  - 完成后：`DataManager.addMoney()`，顾客走向大门并回收到对象池
  - 顾客离店时结算满意度（商品可得性 50% + 排队等待 30% + 环境整洁度 20% + 装修 bonus），写入当日记录

- [ ] **Day 38: 每日流水账记录**
  - 将顾客买走的商品信息推入当日的 `IDailyLedger`
  - 记录当日顾客满意度均值、流失人数，让晚上的"账单复盘"有真实数据

- [ ] **Day 39: 理货员真实补货**
  - 员工完成理货路径后，将 `DataManager.warehouseInventory` 扣除，增加对应货架的库存

- [ ] **Day 40: 午夜扣薪时刻**
  - 关门事件触发时，遍历全体员工 `dailySalary`，从公司总账扣款

- [ ] **Day 41: UI 数值实时绑定**

## 🛟 关键技术难点 Plan B（兜底预案）

> 如果某个技术难点卡住超过 2 天（即 4 小时），立刻启用 Plan B，绝不纠结。

| # | 难点 | 风险等级 | Plan B |
|:--|:-----|:-----|:-----|
| 1 | A* 寻路死锁 / 角色卡墙角 | 🔴 高 | 角色移动超过 5 秒未到达目标 → 强制瞬移到目标坐标（此条已纳入黄金守则） |
| 2 | 排队系统过于复杂 | 🔴 高 | 降级为"收银台前最多 3 人排队"。超出的顾客不排队，直接瞬移到出口自动结算 |
| 3 | Cocos Creator 粒子系统难以上手 | 🟡 中 | 弃用粒子系统，改用 "Sprite 帧动画 + Tween 位移动画" 模拟金币特效 |
| 4 | 多店铺动态重载地图 Bug 频发 | 🟡 中 | 降级为简单方案：切换店铺时直接清空场景所有节点，重新加载新地图 Prefab（允许短暂黑屏） |
| 5 | A* 寻路库引入失败 / 编译不过 | 🟡 中 | 手写简易网格寻路（BFS 替代 A*），损失部分性能但保证能跑 |
| 6 | 第 1 周转眼破产的数值崩坏 | 🟢 低 | 暴力兜底：第 1 周结束后自动判断是否稳亏，若是则弹出"建议重新开始并降低进货量"的提示，同时延长新手保护期到第 2 周 |

> 💡 **原则**：Plan B 不是妥协，是专业的风险管理。先让游戏能跑，再在后续迭代中优雅化。

## ⚠️ 单人开发黄金守则

> 1. 🎨 **不要做任何"锦上添花"的美术活**：用白块代替收银台，用蓝块代替货架。只要 Click 逻辑跑通，最后一天再换图。
>
> 2. 🩹 **"如果今天卡住了，就做个假的"**：如果 A\* 寻路有 10% 的几率卡死解决不了，就写个保底脚本，卡住 5 秒的角色直接强行瞬间移动到目标点。**完成比完美更重要。**
>
> 3. ⏰ **严格遵守 2 小时限制**：到点必须关电脑。这能让你每天都对第二天的开发保持渴望，而不是迅速燃尽热情。
